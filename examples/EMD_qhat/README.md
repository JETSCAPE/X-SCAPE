# EMD holographic q̂ in X-SCAPE: how to run and reproduce

This folder reproduces every result of the study that replaces JETSCAPE's jet
quenching parameter by the q̂(T) of an Einstein–Maxwell–Dilaton (EMD)
holographic model: the brick tests, the full-hydro (TRENTo + free streaming +
MUSIC) comparisons at RHIC and the LHC, the λ_t calibration to data, and the
comparison of the fitted q̂ with JETSCAPE's Bayesian extractions. Every
configuration that was run is regenerated by name with `make_configs.py`.

## What this branch adds

| Commit / file | What |
|---|---|
| `src/jet/EMDQhat.h` | EMD fit Q(T) = q̂_A/(√λ_t T³) at μ_B = 0 (mean deviation 0.12% from `data/qhat_muB0.dat`, 20–800 MeV) |
| `src/jet/HTLQhat.h` | MATTER's HTL q̂(T, E) (Type 1/5 below Q₀), for like-for-like comparisons |
| `src/jet/Matter.{h,cc}` | `QhatParametrizationType` 8 (EMD) and 9 (EMD × the Type-5 virtuality factor); `lambda_t`, `qhat_K`, `conformal_Tref` |
| `src/jet/MyEloss.{h,cc}` | low-virtuality module: BDMPS-Z radiation with a formation-time constraint, broadening, optional elastic recoils; `qhat_model` 0 = EMD, 1 = HTL |
| `src/jet/LBT.{h,cc}` | `qhat_model` 1: LBT's radiative q̂ replaced by the EMD q̂ (elastic scattering and heavy quarks unchanged) |
| `config/jetscape_main.xml` | defaults for all new parameters; existing setups are unchanged |
| `config/jetscape_user_brick_EMD_*.xml` | two ready-to-run bricks |
| bug-fix commit | uninitialized `hydro_tau_0` / `tStart` (MATTER, LBT, AdS/CFT) and `tau_eta_is_tz` / `boost_invariant` in per-event hydro mode; **needed to reproduce the hydro results** (with it a clean build reproduces them bit for bit) |
| colored-hadronization fix (from branch `fix-colored-hadronization`) | MATTER's uninitialized `max_color` after photon radiation, and `ColoredHadronization` now checks `pythia.next()` instead of writing unhadronized partons; changes nothing in colorless runs (checked bit for bit) |
| `examples/EMD_qhat/` | this folder: configurations, run scripts, analysis, data tables |

### Conventions

* The holographic q̂ comes from a light-like **adjoint** Wilson loop
  (Liu, Rajagopal, Wiedemann, hep-ph/0605178), so it is the **gluon** q̂:
  q̂_g = √λ_t · Q(T) · T³. Quarks get C_F/C_A = 4/9 of it (Casimir scaling;
  the large-N_c relation W_A ≈ |W_F|² would give 1/2).
* JETSCAPE quotes q̂ for a **quark**. All comparisons with JETSCAPE bands use
  quark q̂/T³ = (4/9)·√λ_t·Q(T).
* λ_t (the 't Hooft coupling) only sets the overall size of q̂; the model fixes
  the temperature shape.

### The two ways the EMD q̂ is used

* **Route A**: MATTER (Type 9) + **MyEloss**, with the EMD q̂, or for
  comparison the HTL q̂, in both stages.
* **Route B**: the default JETSCAPE chain, MATTER (Type 9) + **LBT** with
  `qhat_model=1`; only q̂(T) differs from the JETSCAPE tune. This is the
  route used for the calibration and the final comparisons.

The reference ("tune", "default") is JETSCAPE MATTER+LBT: Type-5 HTL q̂ with
virtuality factor A = 10, B = 100, α_s = 0.3, Q₀ = 2 GeV, as in the JETSCAPE
Bayesian analyses (PRC 104, 024905 (2021); PRC 111, 054913 (2025)).

## 0. Start here (for students)

Work through the steps in this order. Each one checks the previous one before
you spend more compute.

| Step | What you run | Time | You should get |
|---|---|---|---|
| a | the environment and the build (sections 0.1 and 1) | ~30 min | `build/runJetscape` |
| b | the two quick bricks (end of section 1) | 2 min | runs without errors |
| c | all bricks and `brick_figures.pdf` (section 3) | ~15 min on 6 cores | the 7 brick figures |
| d | one hydro task, e.g. `./run_task.sh lhc_lbtemd_l2_h16` (section 4) | ~1.5 h | `spec/lhc_lbtemd_l2_h16.spec` |
| e | a few seeds of `pp` and one model group on the cluster | a few hours | a first R_AA from `calibrate_lambda.py` (it skips incomplete λ_t) |
| f | the full groups (section 4), then sections 5 and 6 | ~1 week of cluster time | every table and figure of the write-up |

### 0.1 Environment

Everything runs in the JETSCAPE container `jetscape/base:v2.1`, which has
ROOT, HepMC, Pythia 8, HDF5, GSL, Python with numpy and matplotlib, and the
compilers.

```bash
# laptop / workstation (Docker): keep the repository in ~/jetscape-docker
mkdir -p ~/jetscape-docker && cd ~/jetscape-docker
git clone https://github.com/JETSCAPE/X-SCAPE.git && cd X-SCAPE && git checkout EMD_qhat && cd ..
docker run -it -v ~/jetscape-docker:/home/jetscape-user --name xscape jetscape/base:v2.1
# cluster (Apptainer / Singularity): pull the image once and share it
apptainer pull jetscape_base_v2.1.sif docker://jetscape/base:v2.1
apptainer shell -B <your jetscape-docker dir>:/home/jetscape-user jetscape_base_v2.1.sif
```

Inside the container the repository is `/home/jetscape-user/X-SCAPE`; build
and run from there (section 1).

### 0.2 Compute budget and cluster etiquette

* A hydro task is about 1.5 h at the LHC and 0.5 h at RHIC on 2 threads; the
  full study is about 2100 tasks (a few thousand core-hours).
* Run the big groups on a cluster with `slurm/array.sbatch`, and **cap the
  array** (`--array=1-N%50`) when the allocation is shared.
* Never rebuild a build that running tasks use (they die with SIGBUS). Use one
  build per study, and rebuild only when your queue is empty.
* With `KEEP_EVENTS=1` the `bestfit` group needs about 17 GB of disk.
* A failed task is rerun with the same `sbatch` line: finished tasks are
  skipped (`done/<task>`), and a rerun gives bit-identical output.

### 0.3 Which step makes which result

| Result | Groups | Script |
|---|---|---|
| brick figures (validation, EMD vs HTL, path length, route B) | `bricks` | `brick_qhat_compare.py`, `brick_figures.tex` |
| route A at RHIC and the LHC (EMD and HTL alike) | `pp`, `routeA` | `final_analysis.py`, `paired_analysis.py` |
| route B, double ratios (no temperature-shape effect) | `pp`, `routeA`, `routeB` | `option1_analysis.py` |
| λ_t calibration (λ_t ≈ 2.4 from ATLAS jets) | `pp`, `routeA` (tune), `routeB`, `lamcal`, `lamext` | `calibrate_lambda.py` |
| EMD at λ_t = 2.4 vs the default, many observables | `bestfit` | `x_compare.py` |
| χ² against ATLAS, CMS and ALICE jet data | `bestfit`, then `jetana_data` | `data_compare.py` |
| pp baseline (MPI, hadronization, shower, PYTHIA) | `bestfit`, `ppvar`, PYTHIA | `pp_variants.py` |

### 0.4 Troubleshooting

* `Illegal instruction` from numpy on a cluster login node: run Python with
  `FLEXIBLAS=NETLIB` (e.g. `apptainer exec --env FLEXIBLAS=NETLIB ...`), or use
  `slurm/analysis.sbatch`.
* A hydro run that differs from the published numbers: check that the build
  includes the bug-fix commit (uninitialized `hydro_tau_0`).
* Colored hadronization writing partons or failing every event: the build
  lacks the colored-hadronization fix of this branch.
* Two tasks sharing a working directory corrupt MUSIC's `music_input`; always
  start tasks with `run_task.sh`, which gives each its own `/tmp` directory.

## 1. Build

```bash
git clone https://github.com/JETSCAPE/X-SCAPE.git && cd X-SCAPE && git checkout EMD_qhat
cd external_packages
./get_lbtTab.sh                              # LBT tables (needed for any LBT run)
./get_music.sh && ./get_freestream-milne.sh  # only for the hydro runs
cd .. && mkdir -p build && cd build
cmake .. -DUSE_MUSIC=ON -DUSE_FREESTREAM=ON && make -j8
```

The study used the `jetscape/base:v2.1` Docker image (Apptainer on a SLURM
cluster). The analysis scripts need Python 3 with numpy and matplotlib (the
brick analysis needs only plain Python), and LaTeX with pgfplots for the brick
and q̂ figures.

Quick test (about 1 min each):

```bash
cd build
./runJetscape ../config/jetscape_user_brick_EMD_MatterLbt.xml ../config/jetscape_main.xml
./runJetscape ../config/jetscape_user_brick_EMD_MatterMyEloss.xml ../config/jetscape_main.xml
```

## 2. Set up the study folder

Work inside this folder, or in a copy (then set `XSCAPE=<repository>` and, if
the build is elsewhere, `BUILD=<build dir>`).

```bash
cd examples/EMD_qhat
g++ -O2 -std=c++17 -I../../external_packages jetana.cc ../../external_packages/fjcore.cc -o jetana
python3 make_configs.py            # all groups, or e.g.  python3 make_configs.py bricks pp
```

`make_configs.py` writes `configs/<name>.xml` and `tasks/<group>.txt`. The
configurations are identical, apart from the output path, to the ones that
produced the results (checked file by file).

| Group | Tasks | What |
|---|---|---|
| `bricks` | 70 | all bricks of `brick_figures.pdf` (route A EMD/HTL, path length, route B) |
| `pp` | 24 | pp baselines, LHC 5.02 TeV (16 × 25k events) and RHIC 200 GeV (8 × 25k) |
| `routeA` | 435 | MATTER+MyEloss: EMD (λ_t = 256), HTL (K = 16.4) and the tune; RHIC and LHC, 0–10% and 30–50% |
| `routeB` | 665 | MATTER+LBT with the EMD q̂: λ_t = 2 (all samples), 2.6 and 8 (0–10%), and extra tune runs |
| `lamcal` | 285 | λ_t = 1, 1.5, 3 at the LHC, 0–10% and 30–50%, for the χ² calibration |
| `lamext` | 190 | λ_t = 4.5, 6 at the LHC, 0–10% and 30–50%: extends the calibration grid |
| `bestfit` | 454 | λ_t = 2.4 (best fit) against the tune, RHIC and LHC, 0–10% and 30–50%, plus pp; run with `KEEP_EVENTS=1` |
| `ppvar` | 56 | LHC pp with PYTHIA MPI off, colored or hybrid hadronization, and parton-shower variants (8 × 25k each); run with `KEEP_EVENTS=1` |

A hydro task is one TRENTo + free-streaming + MUSIC event reused for 2500
p̂_T-biased Pythia hard events: about 1.5 h at the LHC and 0.5 h at RHIC on 2
threads. Tasks of different models with the same hydro seed see the same hydro
event and the same hard scatterings ("paired"), which allows the event-by-event
comparisons below.

## 4. Full hydro

```bash
python3 make_configs.py pp routeA routeB lamcal lamext bestfit ppvar
# on a SLURM cluster, from this folder, one group at a time, e.g.
sbatch --account=<acct> --array=1-$(wc -l < tasks/pp.txt) --export=ALL,TASKS=tasks/pp.txt slurm/array.sbatch
sbatch --account=<acct> --array=1-$(wc -l < tasks/bestfit.txt)%50 \
       --export=ALL,TASKS=tasks/bestfit.txt,KEEP_EVENTS=1 slurm/array.sbatch
sbatch --account=<acct> --array=1-$(wc -l < tasks/ppvar.txt)%50 \
       --export=ALL,TASKS=tasks/ppvar.txt,KEEP_EVENTS=1 slurm/array.sbatch
#   container: add IMAGE=<jetscape_base_v2.1.sif>,BIND=<paths> to --export
# or locally, one task at a time:
./run_task.sh lhcx_lbtemd_l2p4_h16
```

Each task leaves `spec/<task>.spec` (weighted spectra, jet substructure and
the observables below, from `jetana`), `logs/<task>.log` and `done/<task>`.
With `KEEP_EVENTS=1` it also keeps the final-state hadrons in
`events/<task>.dat.gz`. The `bestfit` group takes about 17 GB, and `jetana` can be rerun on
these files (`zcat ... | ./jetana out.spec /dev/stdin`) to add observables or
change cuts without rerunning JETSCAPE.

`jetana` measures, with fjcore anti-k_T and JETSCAPE hole subtraction:

* jet R_AA (ATLAS-, ALICE-charged- and sPHENIX-like acceptances), charged-hadron
  R_AA, jet spectra for R = 0.2, 0.4, 0.6
* per jet, in jet-p_T bins: E2C (EEC), jet mass, angularities λ₀.₅, girth, λ₂
* dijet x_J (ATLAS-like), fragmentation functions D(z) and D(p_T) (ATLAS-like),
  jet shape ρ(r) (CMS-like) and the charged-jet mass (ALICE-like). The cuts are
  listed at the top of `jetana.cc`; they follow the measurements approximately
  and should be matched to the HEPData selections before comparing with data.

## 5. Comparison with data (step 2)

`jetana_data` re-analyses the kept events with the selections and the bins of
the HEPData records in `data/hepdata/` (one CSV per table):

| Measurement | HEPData | Model selection (see the top of `jetana_data.cc`) |
|---|---|---|
| ATLAS dijet x_J, pp and 0–10% | ins2075431 | R = 0.4, two leading jets with \|y\| < 2.1, Δφ > 7π/8, x_J ≥ 0.32, self-normalised, 11 p_T,1 bins |
| ATLAS D(z), pp and PbPb/pp | ins1673177 | R = 0.4, \|y\| < 2.1, 126–398 GeV, tracks p_T > 1 GeV in ΔR < 0.4; UE from perpendicular cones |
| CMS ρ(Δr), pp, 0–10%, 30–50% | ins1658057 | R = 0.4, p_T > 120 GeV, \|η\| < 1.6, tracks p_T > 0.7 GeV; UE from the 1.5 < \|Δη\| < 2.5 sideband (the CMS method) |
| ALICE m and λ_α, pp and 0–10% | ins2845788 | charged R = 0.2, \|η\| < 0.7, 40–150 GeV, every charged particle with the pion mass (as ALICE's tracks); Soft Drop z_cut = 0.2, β = 0 with holes reclustered as negative constituents |

```bash
g++ -O2 -std=c++17 -I../../external_packages jetana_data.cc ../../external_packages/fjcore.cc -o jetana_data
cat tasks/bestfit.txt tasks/ppvar.txt > tasks/data.txt
sbatch --account=<acct> --array=1-$(wc -l < tasks/data.txt)%50 \
       --export=ALL,TASKS=tasks/data.txt slurm/data_array.sbatch    # ~15 s per file
sbatch --account=<acct> --array=1-$(wc -l < tasks/data.txt)%50 \
       --export=ALL,TASKS=tasks/data.txt,PIONMASS=1 slurm/data_array.sbatch   # for ALICE
# standalone PYTHIA 8 pp reference (needs pythia8-config, e.g. in the JETSCAPE image)
g++ -O2 -std=c++17 $(pythia8-config --cxxflags) pythia_pp.cc -o pythia_pp $(pythia8-config --libs)
sbatch --account=<acct> --array=1-16%50 slurm/pythia_array.sbatch
python3 data_compare.py         # data_compare.txt, fig_data_{xj,ff,cms,alice_mass,alice_ang}.png
python3 pp_variants.py          # hadronization and MPI: pp_variants.txt, fig_pp_variants.png
python3 pp_variants.py shower   # parton shower: pp_shower.txt, fig_pp_shower.png
python3 pp_variants.py pythia   # vs standalone PYTHIA, true vs pion mass: pp_pythia.txt, fig_pp_pythia.png
```

`data_compare.py` uses χ² = rᵀC⁻¹r with the data and model statistical and
systematic uncertainties. ALICE's signed "trkeff" and "generator" sources are
treated as fully correlated across bins, as its record states. The other
records give no correlations, so their uncertainties are taken as
uncorrelated; ALICE is also reported that way ("diag").

## 7. Results in brief

| | Value |
|---|---|
| λ_t from the χ² fit to ATLAS jets (route B) | **2.4** (2.0–4.0, depending on the treatment of systematics); charged hadrons prefer > 3 |
| quark q̂/T³ at T = 0.3 GeV for λ_t = 2.4 | ≈ 7.0, on the JETSCAPE 2025 "Combined" median |
| λ_t that reproduces the JETSCAPE tune (route B) | ≈ 1.6; in a T = 0.3 GeV brick, λ_t = 1 |
| route A (MyEloss) normalisation | λ_t = 256 (kernel-specific: coherent BDMPS-Z radiation is suppressed at short path length); HTL K = 16.4 |
| λ_t used by Khan et al. (arXiv:2603.20482) | 1/25–1/9, compared without C_F/C_A to the JETSCAPE 2021 band at μ² ≈ (2.7 GeV)²; as quark q̂/T³ ≈ 1.1 at 0.3 GeV |

* At matched normalisation the EMD and JETSCAPE q̂(T) give the same jet and
  hadron R_AA, its R, centrality and √s dependence, E2C, jet mass,
  angularities, x_J, D(z), ρ(r) and charged-jet mass to 2–3%. The two
  temperature shapes differ mainly near T_c, where jets lose little energy.
* At the best fit λ_t = 2.4 the EMD q̂ suppresses 3–7% (RHIC 0–10%: 14%) more
  jets than the default, which lies slightly above the ATLAS data in this
  setup; the few 2–3σ substructure differences follow the same stronger
  quenching.
* Normalising to data needs λ_t ≈ 2.4 > 1, as the holographic dictionary
  assumes. The much smaller λ_t ≈ 1/16 of Khan et al. came from comparing the
  adjoint EMD q̂ with the quark q̂ without C_F/C_A = 4/9; the EMD authors agree
  (October 2026), so the normalisation puzzle is resolved. Open: 4/9 (Casimir)
  or 1/2 (large N_c), a 12% difference in q̂.
* Against data (`data_compare.txt`), neither q̂ is preferred: the Δχ² between
  EMD (λ_t = 2.4) and the default are small next to the χ² themselves and
  change sign between observables (ATLAS x_J +13 over 110 bins, R_D(z) +9 over
  89, CMS ρ −26 over 42, ALICE mass −9 over 40 and groomed mass +9 over 47,
  ALICE angularities +56 over 116). Both describe the ALICE jet mass in pp
  and Pb–Pb (χ² 25/28 in pp, 47–56/40 in Pb–Pb) and share the same misses:
  too little enhancement at low z in 0–10% R_D(z) and at large Δr in the CMS
  PbPb/pp jet shape.
* pp baseline (`pp_variants.txt`): the extra soft, wide-angle particles in pp
  jets are mostly an uncorrelated underlying event: PythiaGun switches PYTHIA
  MPI on and passes the MPI partons through MATTER. With the CMS sideband
  subtraction, colorless hadronization comes within about 30% of CMS at
  large Δr (χ² 258/14, against 1800 without the subtraction). Colored
  hadronization, which follows MATTER's colour flow, narrows it further
  (χ² 140/14, and 87/14 with MPI off) and improves the low-p_T ATLAS pp D(z)
  (87/21 against 170/21), with the same x_J. Standalone PYTHIA 8 describes
  CMS ρ best (χ² 31/14), so the remaining wide-angle excess comes from the
  strings and remnants of the JETSCAPE chain. The parton
  shower is not the problem (`pp_shower.txt`): PYTHIA's own shower, MATTER
  with Q0 = 2 GeV or vir_factor 0.1 change the ALICE jet mass by ≤ 0.2 GeV.
* ALICE jet mass (`pp_pythia.txt`): ALICE gives every track the pion mass.
  With true hadron masses, protons and kaons make R = 0.2 jets 0.6–1.2 GeV
  heavier; with the pion mass the JETSCAPE pp mean mass is 3.16/4.10/5.02
  GeV against ALICE's 3.17/4.00/4.72 at 40–60/60–80/80–100 GeV.

## Notes

* `MyEloss` and LBT must not run together (a mutex enforces it).
* Do not rebuild the build that running tasks use: a running `runJetscape`
  whose shared libraries change dies with SIGBUS.
* MUSIC writes and re-reads `music_input` in the working directory;
  `run_task.sh` gives each task its own `/tmp` working directory for this reason.
* The route-A recoil option (`recoil_on`) is implemented and validated in a
  brick (energy conservation exact, ⟨k_T²⟩ = 90% of q̂L) but no result uses it.
* Colored hadronization needs the fix on this branch. Without it, MATTER
  leaves `max_color` uninitialized after photon radiation, colour tags
  overflow, PYTHIA fails ("junction topology inconsistent"), and
  `ColoredHadronization`, which ignored a failed `pythia.next()`, writes the
  unhadronized partons of every later event of the run. With the fix PYTHIA
  still fails on 1–6 events in 25k, which now get no hadrons. `jetana_data`
  still skips and counts any event with quarks or gluons in the final state
  ("skipped"); no sample here has any.
* PythiaGun hard-codes `PartonLevel:MPI = on`, and the MPI partons go through
  MATTER and hadronization; `PartonLevel:MPI = off` in its `LinesToRead`
  overrides it.
* Reproducibility: rerunning a task with the same configuration gives
  bit-identical output; the `bestfit` default and pp runs reproduce the
  earlier production spectra exactly.
