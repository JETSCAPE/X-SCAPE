# EMD holographic q̂ in X-SCAPE: how to run and reproduce

This folder reproduces every result of the study that replaces JETSCAPE's jet
quenching parameter by the q̂(T) of an Einstein–Maxwell–Dilaton (EMD)
holographic model: the brick tests, the full-hydro (TRENTo + free streaming +
MUSIC) comparisons at RHIC and the LHC, the λ_t calibration to data, and the
comparison of the fitted q̂ with JETSCAPE's Bayesian extractions. Every
configuration that was run is regenerated by name with `make_configs.py`.

## What this branch adds

| Commit / file | What |
|---|---|
| `src/jet/EMDQhat.h` | EMD fit Q(T) = q̂_A/(√λ_t T³) at μ_B = 0 (mean deviation 0.12% from `data/qhat_muB0.dat`, 20–800 MeV) |
| `src/jet/HTLQhat.h` | MATTER's HTL q̂(T, E) (Type 1/5 below Q₀), for like-for-like comparisons |
| `src/jet/Matter.{h,cc}` | `QhatParametrizationType` 8 (EMD) and 9 (EMD × the Type-5 virtuality factor); `lambda_t`, `qhat_K`, `conformal_Tref` |
| `src/jet/MyEloss.{h,cc}` | low-virtuality module: BDMPS-Z radiation with a formation-time constraint, broadening, optional elastic recoils; `qhat_model` 0 = EMD, 1 = HTL |
| `src/jet/LBT.{h,cc}` | `qhat_model` 1: LBT's radiative q̂ replaced by the EMD q̂ (elastic scattering and heavy quarks unchanged) |
| `config/jetscape_main.xml` | defaults for all new parameters; existing setups are unchanged |
| `config/jetscape_user_brick_EMD_*.xml` | two ready-to-run bricks |
| bug-fix commit | uninitialized `hydro_tau_0` / `tStart` (MATTER, LBT, AdS/CFT) and `tau_eta_is_tz` / `boost_invariant` in per-event hydro mode; **needed to reproduce the hydro results** (with it a clean build reproduces them bit for bit) |
| `examples/EMD_qhat/` | this folder: configurations, run scripts, analysis, data tables |

### Conventions

* The holographic q̂ comes from a light-like **adjoint** Wilson loop
  (Liu, Rajagopal, Wiedemann, hep-ph/0605178), so it is the **gluon** q̂:
  q̂_g = √λ_t · Q(T) · T³. Quarks get C_F/C_A = 4/9 of it (Casimir scaling;
  the large-N_c relation W_A ≈ |W_F|² would give 1/2).
* JETSCAPE quotes q̂ for a **quark**. All comparisons with JETSCAPE bands use
  quark q̂/T³ = (4/9)·√λ_t·Q(T).
* λ_t (the 't Hooft coupling) only sets the overall size of q̂; the model fixes
  the temperature shape.

### The two ways the EMD q̂ is used

* **Route A**: MATTER (Type 9) + **MyEloss**, with the EMD q̂, or for
  comparison the HTL q̂, in both stages.
* **Route B**: the default JETSCAPE chain, MATTER (Type 9) + **LBT** with
  `qhat_model=1`; only q̂(T) differs from the JETSCAPE tune. This is the
  route used for the calibration and the final comparisons.

The reference ("tune", "default") is JETSCAPE MATTER+LBT: Type-5 HTL q̂ with
virtuality factor A = 10, B = 100, α_s = 0.3, Q₀ = 2 GeV, as in the JETSCAPE
Bayesian analyses (PRC 104, 024905 (2021); PRC 111, 054913 (2025)).

## 1. Build

```bash
git clone https://github.com/JETSCAPE/X-SCAPE.git && cd X-SCAPE && git checkout EMD_qhat
cd external_packages
./get_lbtTab.sh                              # LBT tables (needed for any LBT run)
./get_music.sh && ./get_freestream-milne.sh  # only for the hydro runs
cd .. && mkdir -p build && cd build
cmake .. -DUSE_MUSIC=ON -DUSE_FREESTREAM=ON && make -j8
```

The study used the `jetscape/base:v2.1` Docker image (Apptainer on a SLURM
cluster). The analysis scripts need Python 3 with numpy and matplotlib (the
brick analysis needs only plain Python), and LaTeX with pgfplots for the brick
and q̂ figures.

Quick test (about 1 min each):

```bash
cd build
./runJetscape ../config/jetscape_user_brick_EMD_MatterLbt.xml ../config/jetscape_main.xml
./runJetscape ../config/jetscape_user_brick_EMD_MatterMyEloss.xml ../config/jetscape_main.xml
```

## 2. Set up the study folder

Work inside this folder, or in a copy (then set `XSCAPE=<repository>` and, if
the build is elsewhere, `BUILD=<build dir>`).

```bash
cd examples/EMD_qhat
g++ -O2 -std=c++17 -I../../external_packages jetana.cc ../../external_packages/fjcore.cc -o jetana
python3 make_configs.py            # all groups, or e.g.  python3 make_configs.py bricks pp
```

`make_configs.py` writes `configs/<name>.xml` and `tasks/<group>.txt`. The
configurations are identical, apart from the output path, to the ones that
produced the results (checked file by file).

| Group | Tasks | What |
|---|---|---|
| `bricks` | 70 | all bricks of `brick_figures.pdf` (route A EMD/HTL, path length, route B) |
| `pp` | 24 | pp baselines, LHC 5.02 TeV (16 × 25k events) and RHIC 200 GeV (8 × 25k) |
| `routeA` | 435 | MATTER+MyEloss: EMD (λ_t = 256), HTL (K = 16.4) and the tune; RHIC and LHC, 0–10% and 30–50% |
| `routeB` | 665 | MATTER+LBT with the EMD q̂: λ_t = 2 (all samples), 2.6 and 8 (0–10%), and extra tune runs |
| `lamcal` | 285 | λ_t = 1, 1.5, 3 at the LHC, 0–10% and 30–50%, for the χ² calibration |
| `bestfit` | 454 | λ_t = 2.4 (best fit) against the tune, RHIC and LHC, 0–10% and 30–50%, plus pp; run with `KEEP_EVENTS=1` |

A hydro task is one TRENTo + free-streaming + MUSIC event reused for 2500
p̂_T-biased Pythia hard events: about 1.5 h at the LHC and 0.5 h at RHIC on 2
threads. Tasks of different models with the same hydro seed see the same hydro
event and the same hard scatterings ("paired"), which allows the event-by-event
comparisons below.

## 4. Full hydro

```bash
python3 make_configs.py pp routeA routeB lamcal bestfit
# on a SLURM cluster, from this folder, one group at a time, e.g.
sbatch --account=<acct> --array=1-$(wc -l < tasks/pp.txt) --export=ALL,TASKS=tasks/pp.txt slurm/array.sbatch
sbatch --account=<acct> --array=1-$(wc -l < tasks/bestfit.txt)%80 \
       --export=ALL,TASKS=tasks/bestfit.txt,KEEP_EVENTS=1 slurm/array.sbatch
#   container: add IMAGE=<jetscape_base_v2.1.sif>,BIND=<paths> to --export
# or locally, one task at a time:
./run_task.sh lhcx_lbtemd_l2p4_h16
```

Each task leaves `spec/<task>.spec` (weighted spectra, jet substructure and
the observables below, from `jetana`), `logs/<task>.log` and `done/<task>`.
With `KEEP_EVENTS=1` it also keeps the final-state hadrons in
`events/<task>.dat.gz`. The `bestfit` group takes about 17 GB, and `jetana` can be rerun on
these files (`zcat ... | ./jetana out.spec /dev/stdin`) to add observables or
change cuts without rerunning JETSCAPE.

`jetana` measures, with fjcore anti-k_T and JETSCAPE hole subtraction:

* jet R_AA (ATLAS-, ALICE-charged- and sPHENIX-like acceptances), charged-hadron
  R_AA, jet spectra for R = 0.2, 0.4, 0.6
* per jet, in jet-p_T bins: E2C (EEC), jet mass, angularities λ₀.₅, girth, λ₂
* dijet x_J (ATLAS-like), fragmentation functions D(z) and D(p_T) (ATLAS-like),
  jet shape ρ(r) (CMS-like) and the charged-jet mass (ALICE-like). The cuts are
  listed at the top of `jetana.cc`; they follow the measurements approximately
  and should be matched to the HEPData selections before comparing with data.

## 5. Analysis → figures and tables

Run in the container or with `slurm/analysis.sbatch` (`--export=ALL,SCRIPT=<script>`).

| Script | Needs | Produces |
|---|---|---|
| `final_analysis.py` | pp, routeA | route A vs CMS, ATLAS, ALICE: `fig_data_0010.png`, `fig_data_3050.png`; `fig_rhic.png`, `fig_centrality.png`, `fig_radius.png`, `fig_sub_<sample>.png`; EMD-vs-HTL significance table |
| `paired_analysis.py` | routeA | paired ln(EMD/HTL) per hydro event |
| `option1_analysis.py` | pp, routeA (tune), routeB | route B: `option1.png`; paired EMD/tune differences and RHIC-vs-LHC double ratios |
| `calibrate_lambda.py` | pp, routeA, routeB, lamcal | χ²(λ_t) against ATLAS jets and CMS hadrons, both centralities: `lamcal.txt`, `fig_lamcal.png` |
| `e2c_bestfit.py` | pp, routeA, routeB, lamcal | E2C around the best fit (λ_t = 2 and 3, 2.4 interpolated): `fig_e2c_bestfit*.png` |
| `x_compare.py` | bestfit | λ_t = 2.4 vs the default, paired: R_AA, E2C, mass, angularities, x_J, D(z), ρ(r), charged-jet mass: `x_compare.txt`, `fig_x_raa_e2c.png`, `fig_x_newobs.png` |
| `qhat_comparison/qhat_overlay.tex` | (data files here) | quark q̂/T³: JETSCAPE 2025 "Combined" band (E = 100 GeV, μ² = Q₀²), the JETSCAPE 2021 band used in Khan et al. Fig. 10, the EMD q̂ at λ_t = 1/25–1/9 and at the fitted λ_t |

`data/` holds the HEPData tables used (ATLAS 30–50% is the average of the
30–40% and 40–50% tables) and `qhat_muB0.dat`, the EMD input that
`EMDQhat.h` fits. The JETSCAPE bands in `qhat_comparison/` are digitized from
the published figures (±0.1–0.2 in q̂/T³); `make_emd_curves.py` writes the
EMD curves.

## 6. Results in brief

| | Value |
|---|---|
| λ_t from the χ² fit to ATLAS jets (route B) | **2.4** (2.0–4.0, depending on the treatment of systematics); charged hadrons prefer > 3 |
| quark q̂/T³ at T = 0.3 GeV for λ_t = 2.4 | ≈ 7.0, on the JETSCAPE 2025 "Combined" median |
| λ_t that reproduces the JETSCAPE tune (route B) | ≈ 1.6; in a T = 0.3 GeV brick, λ_t = 1 |
| route A (MyEloss) normalisation | λ_t = 256 (kernel-specific: coherent BDMPS-Z radiation is suppressed at short path length); HTL K = 16.4 |
| λ_t used by Khan et al. (arXiv:2603.20482) | 1/25–1/9, compared without C_F/C_A to the JETSCAPE 2021 band at μ² ≈ (2.7 GeV)²; as quark q̂/T³ ≈ 1.1 at 0.3 GeV |

* At matched normalisation the EMD and JETSCAPE q̂(T) give the same jet and
  hadron R_AA, its R, centrality and √s dependence, E2C, jet mass,
  angularities, x_J, D(z), ρ(r) and charged-jet mass to 2–3%. The two
  temperature shapes differ mainly near T_c, where jets lose little energy.
* At the best fit λ_t = 2.4 the EMD q̂ suppresses 3–7% (RHIC 0–10%: 14%) more
  jets than the default, which lies slightly above the ATLAS data in this
  setup; the few 2–3σ substructure differences follow the same stronger
  quenching.
* Normalising to data needs λ_t about 40 times the 1/16 of Khan et al. (q̂
  about 6 times larger), toward the large-coupling regime of holography.

## Notes

* `MyEloss` and LBT must not run together (a mutex enforces it).
* Do not rebuild the build that running tasks use: a running `runJetscape`
  whose shared libraries change dies with SIGBUS.
* MUSIC writes and re-reads `music_input` in the working directory;
  `run_task.sh` gives each task its own `/tmp` working directory for this reason.
* The route-A recoil option (`recoil_on`) is implemented and validated in a
  brick (energy conservation exact, ⟨k_T²⟩ = 90% of q̂L) but no result uses it.
* Reproducibility: rerunning a task with the same configuration gives
  bit-identical output; the `bestfit` default and pp runs reproduce the
  earlier production spectra exactly.
